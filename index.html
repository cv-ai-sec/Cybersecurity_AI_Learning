LLM Security Labs

A hands-on OWASP Top 10 for LLMs red team / blue team series, run entirely against local models. Progress is tracked in your browser only — nothing is sent anywhere.

Purpose

Upskilling in AI security by actually red-teaming and then defending real LLM application patterns — prompt injection, agentic tool-execution, RAG/vector poisoning — against models running on local infrastructure. Every attack shown was actually run; every defense was re-run against the same attack to confirm it holds.

Key Takeaways

  • Structuring output (JSON/schema) can weaken a model's adherence to safety instructions — validate business logic in code, not just shape.
  • Untrusted data (logs, RAG documents, tool outputs) must be wrapped and treated as inert data, never as instructions, regardless of how authoritative it reads.
  • An LLM connected to real tools/APIs needs least-privilege scoping and human approval for any consequential action.
  • Vector search relevance is not a security boundary; RAG pipelines need the same access control and provenance thinking as any other data source.
